# 订阅账号的环境时区

Claude、ChatGPT/Codex、Grok 订阅账号在发送推理请求时，可按账号出口时区更新已确认的客户端环境信息。绑定订阅号时可填写 IANA 时区，例如 `America/Los_Angeles`；账号管理中的「时区」页可修改，清空后恢复自动识别。美国有多个时区，不能将所有美国 IP 映射成同一个时区。

## 识别顺序

1. 使用账号的手动时区覆盖。写入时校验 IANA 名称，并与代理设置一同保存在已有的加密配置中；刷新 OAuth token 不会覆盖它。
2. 没有覆盖时，通过该执行客户端固定的代理依次请求 [IPWho.is](https://ipwhois.io/documentation) 和 [ipapi.is](https://ipapi.is/developers.html)。两者公开提供免费额度；不使用付费账户、API key 或自动升级。服务只根据连接来源定位，不接收订阅账号、Token、用户输入或指定 IP 参数。
3. 成功结果按代理配置缓存 15 分钟，同一出口的并发请求共用一次探测。单个服务最多等 2 秒，响应正文上限 32 KiB。失败结果缓存 1 分钟，全部失败返回「未识别」，保持请求不变，不采用服务器时区或国家猜测值。

缓存只留时区、来源和检测时间，不保存 IP；代理凭证只参与内存缓存键的 SHA-256 摘要。管理接口受既有管理员鉴权保护。

## 转换范围

| 客户端 | 已确认的发送内容 | 行为 |
| --- | --- | --- |
| Codex | user 消息中独立的 `<environment_context>`，含唯一 `<current_date>` 和 `<timezone>` | 写入目标 IANA 时区及发送时该时区的日期 |
| Claude Code | user 文本块中完整的 `<system-reminder>Today's date is YYYY-MM-DD.</system-reminder>` | 写入发送时目标时区的日期 |
| Grok | user 文本开头的标准 `<user_info>`，同时具有 OS、Shell、Workspace 和日期行 | 仅更新日期行，保留后面的用户正文 |
| Grok | 完整、已知措辞的跨日 `<system-reminder>` | 同时更新其中两处当前日期 |

只处理每类环境块中最近的一条，保留更早的历史日期。采用 `Intl.DateTimeFormat` 的 IANA 规则，自动处理夏令时；不使用固定小时偏移量。原始请求保持不变，每个账号尝试独立生成新正文，并使旧 `raw_body` 失效。原生透传和协议转换后的请求均在上游序列化前处理；HTTP、SSE、Codex WebSocket、compact 和已实现的 token 计数路径共用相应发送边界。修改时区不会重建 Codex 连接池。

没有增加时区 Header：所审查客户端中没有确认自动发送时区的专用 Header。不会扫描或替换任意字符串、用户日程、搜索位置、工具参数、UTC 时间戳、助手消息或引用示例。精确模仿客户端环境块的用户文本无法通过纯文本协议鉴别来源；不将该识别视为身份或权限边界。

目前没有确认三个上游的响应中存在需要反向还原的环境时区字段契约，因此响应 JSON、模型文字、工具参数及 SSE 内容不做时区替换。Grok 独立上传到遥测服务的时间戳不经过 Helm，也不在此功能的处理范围内。

## 准确性限制

- IP 定位库可能有误差。代理若每次连接更换 IP，或按目标网站分配不同出口，探测服务看到的 IP 不一定等于模型服务看到的 IP；15 分钟缓存也无法感知期间的 IP 轮换。需要固定出口或手动覆盖，不能承诺地理位置绝对准确。
- 未知客户端格式保持原样。日期是客户端环境的“当前日期”，不是业务时间的时区换算。
- `previous_response_id` 和 WebSocket 增量续接可能引用已经保存在上游的旧环境信息；网关不能修改未重新发送的历史。时区变更会应用于随后携带的环境块，需要完全更新远端上下文时应新建会话。
- 静态 API-key provider 不启用此功能。账号信息、访问令牌、installation/session 标识及鉴权 Header 的规则保持现有实现。
